# 案例二：作业批改与首错定位

`scenario_id`: `assessment_diagnosis_v1`  
当前完成度：**商业闭环、演示脚本和本地路由材料已完成；真实教师抽检和最终评分一致性待补证据。**

## 1. 定位

一句话：面向教师和助教的步骤级作业初审助手，定位“第一个可确认错误”，给出依据、分层提示和下一道验证题，但不替教师自动定案。

真实问题是批改量大、错误往往出现在中间步骤、只看最终答案会错过教学机会。使用者是教师/助教，付费者是学院教务或智慧教学平台；场景覆盖电路计算、作业批次抽检和错题讲评。自动批改市场数字、单位价格和节省比例**待补证据**。

## 2. 产品与技术

- 产品：教师批次工作台，输入题目、学生作答、标准答案/评分规则，输出首错、证据、提示级别、验证题和人工复核状态。
- 架构：`/workspace` → 非阻塞任务创建 → `assessment_diagnosis_v1` → `TEACH_02_ASSIGNMENT_REVIEW_V1` → 本地/声明降级 → TaskRunner/SSE → 教师抽检。
- 难点：首错与后续连锁错误区分、评分规则引用、不要泄漏完整答案、图片作答的 OCR 不确定性。
- 可行性：注册表声明 `assignment_review`、CT/AE/DE、步骤诊断、rubric 与人工复核；本地 formatter 将 `errors`、`correct_parts`、`review_required` 输出到业务卡片。
- 依赖：课程包/错误池/评分规则；未授权资料不能进入正式交付。

| 版本 | 范围与验收 |
| --- | --- |
| MVP | CT 文本作答，首错+依据+提示+验证题；缺题目或标准答案必须 `review_required=true` |
| 试点版 | CT/AE/DE，作答图片转文字、批次抽检、教师纠正回流；一致性阈值待补证据 |
| 规模化版 | 平台 API、题库版本、班级权限、审计和人工复核队列 |

## 3. 商业模式

付费者为学院教务或智慧教学平台，交付单位是作业批次与教师审核席位。可按处理量、批次或席位收费，价格区间、最低批量和回本周期**待补证据**。获客从一门课/一次作业批次的抽检开始，交付包含规则配置、脱敏、教师抽检和结果导出；复购来自新批次、课程扩展、题库和学情服务。成本包括解析、模型/检索、人工抽检、存储和实施。单位经济用 `批次收入 - 解析/推理成本 - 抽检人时 - 运维` 计算，当前无真实数据。三年路径：单批次试点 → 学院作业平台接入 → 校级教务服务；不把自动评分准确率写成已实现指标。

## 4. 市场与竞争

边界是“教师批改辅助”，不宣称替代教师评分。需求证据来自 `config/scenarios.yaml` 的首错与抽检约束、`agent_configs/registry.yaml` 的 review contract 和现有教学闭环；外部市场、政策和竞品性能**待补证据**。

| 替代 | 局限 | 差异 |
| --- | --- | --- |
| 人工批改 | 周转慢、首错不易统一 | 先定位错误，再让教师确认 |
| 只给对错的题库 | 没有步骤证据与提示层级 | 输出错误证据、hint 和 next check |
| 通用 OCR/大模型 | 可能把不确定内容当事实 | 解析不确定性、规则引用和人工门 |

壁垒来自经授权的评分规则、错误池、教师纠正记录和审计流程；容易复制的是 UI/提示词。应对方式是版本化规则、抽检数据和学校交付流程，而非夸大模型能力。

## 5. 落地计划

- 0—3个月：CT 文本题做3类首错模板；补充标准答案/评分规则合成样例；跑路由、人工复核和不泄漏测试。
- 3—12个月：授权教师抽检 CT/AE/DE；记录首错一致性、教师改判、批次周转和提示采纳；客户和阈值待补证据。
- 12—36个月：接入 LMS/题库、班级权限、复核队列和课程质量分析。
- 分工：教研定义规则；Agent 工程维护诊断；前端做批次审查；实施负责数据脱敏和培训。
- 风险：学生隐私、评分公平、错误归因、OCR 误读、未授权答案泄漏；默认仅初审，禁止自动发布最终分数。
- 里程碑：输入契约、证据卡、教师改判日志、批次复盘和授权试点记录逐项验收。

## 6. 路演表达

**30秒**：我们不让 AI 直接给分，而是帮助教师找到学生解题中第一个可确认错误，并给出来源、分层提示和下一道验证题。教师仍是最终裁决者，系统把批改从“看结果”变成“看证据”。

**3分钟**：教师面对的痛点不是不会判对错，而是批次大、步骤长、错误会连锁。系统绑定课程和评分规则，对作答逐步分析，输出首错、证据和不泄漏提示，教师可抽检、修改并记录结果。商业上按作业批次/审核席位交付，先用一门课验证周转和改判成本，再扩展题库与学情。没有真实抽检前，我们不宣称准确率。

**5分钟答辩要点**：首错需要题目与规则，否则标记不确定；图片识别需保留 OCR 不确定项；评分不自动生效；数据只在授权范围；商业指标以试点记录验证；路由和状态在 TaskRunner 中留痕。

**10问10答**：

1. 谁付费？学院教务或智慧教学平台，需采购访谈核验。
2. 会不会误判？会，所以输出初审与 `review_required`，不自动定分。
3. 首错怎么定义？按规则和步骤证据找到第一个可确认错误，无法确认则降级。
4. 能处理图片吗？当前场景契约为文本；图片需另行批准和 OCR 证据链。
5. 如何防答案泄漏？提示分层，验证题不包含完整解法。
6. 有准确率吗？当前只有结构/路由验证，真实一致性待补证据。
7. 和题库区别？题库给标准答案，本案提供步骤证据与教师闭环。
8. 价格？按批次/席位假设，精确价格待客户验证。
9. 隐私？脱敏、权限、最小留存和审计需写入试点协议。
10. 扩展？新增课程包和规则，不改 Solver 冻结基线。

**商业模式画布**：客户=学院/平台；价值=首错证据+教师可控提示；渠道=作业抽检；收入=批次/席位（待验证）；资源=评分规则/错误池/教师；活动=解析、诊断、抽检；成本=推理、解析、人工审核；伙伴=LMS/题库。

**技术架构一页**：前端上传/文本 → `POST /api/v1/chat` 202 → `TEACH_02_ASSIGNMENT_REVIEW_V1` → 课程规则检索 → 本地 Agent/fallback → SSE 进度 → 首错证据/提示/验证题 → 教师抽检与反馈。

**竞争优势一页**：首错而非单一分数；规则可追溯；人工门；不泄漏；批次闭环。外部竞品对比待补证据。

**路线图一页**：0—3月 CT 文本 → 3—12月授权多课程试点 → 12—36月平台/题库/学情。

**财务一页**：`贡献毛利=批次收入-解析/推理-抽检-运维`；价格、批量、毛利和三年收入待补证据。

## 7. 六个演示案例

| 编号 | 目标与输入 | 操作/路由/知识 | 输出价值 | 失败备用 |
| --- | --- | --- | --- | --- |
| D1 | CT KVL 作答含一个符号错误 | 选场景、粘贴题目/答案；`TEACH_02...`；需评分规则 | 首错+规则依据+提示 | 缺规则则显示不确定与人工复核 |
| D2 | 只给学生分层提示 | 输入学生希望“只给一级提示” | hint level 与验证题，展示不泄漏 | 无法分层时用模板提示 |
| D3 | 识别连锁错误 | 输入含两步依赖错误的解答 | 区分首错/派生错，避免重复批改 | 输出“无法确认”并人工抽检 |
| D4 | 正确部分保留 | 输入部分正确的节点方程 | `correct_parts` 与 `errors` 卡片 | 空答案走边界拒答 |
| D5 | 批次抽检 | 输入三份脱敏答案和同一 rubric | 批次周转和抽检队列 | 仅演示单题并标不代表批量性能 |
| D6 | 风险边界 | 要求自动发布分数/泄漏答案 | 拒绝自动定分，展示复核门 | 前端失败时用 API 任务状态与 JSON |
