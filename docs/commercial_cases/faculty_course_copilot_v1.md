# 案例一：教师智能备课与课程资源生成

`scenario_id`: `faculty_course_copilot_v1`  
当前完成度：**已完成内容闭环；工程接入可本地演示，真实 Provider 与教师试点仍待授权核验。**

## 1. 项目定位

一句话定位：为高校教师和课程团队提供“目标对齐、资料有据、教师可审”的课程备课工作台，把一次备课任务沉淀为可复用课程资产。

真实问题是教师需要在课程目标、章节知识、课堂活动、例题和课后验证之间反复整理资料；现有通用文本工具难以保证课程边界、来源引用和教师最终把关。目标用户是授课教师、助教和课程组，付费客户是学院课程负责人或教师发展中心；使用场景是新课备课、章节迭代、课程群资源复用和教学检查。课程资料治理与生成式 AI 的结合适合先从单门课程、单位教师的低风险工作台试点开始，但市场规模、采购预算和付费意愿仍为**待补证据**。

## 2. 产品与技术方案

- 产品形态：课程工作台，输入课程大纲/主题/教学约束，输出教案草稿、活动设计、形成性评价和来源卡片，教师确认后再导出。
- 核心功能：课程目标拆解、先修关系提示、课堂流程编排、例题/活动候选、课后验证设计、引用与人工复核状态。
- 技术架构：前端 `/demo` 与 `/workspace` → 非阻塞 `POST /api/v1/chat` → TaskRouter 按 `scenario_id` 绑定 `TEACH_01_LESSON_PREP_V1` → 本地课程 RAG/本地 Agent 或声明的降级 → TaskRunner 记录进度、证据卡片和人工复核状态。
- 关键难点：课程目标与生成内容对齐、只使用授权课程资料、长任务状态可观察、教师审查前不自动发布。
- 可行性边界：注册表已声明 `lesson_prep`、CT/AE/DE、文本输入、课程检索和本地适配；本地格式化层只消费结构化字段，缺证据的内容进入 `warnings`，不能当成课程事实。
- 依赖：`config/course_assets/*.yaml`、课程索引、`TEACH_01_LESSON_PREP_V1` 能力契约和本地模型/检索运行时；不依赖硬编码凭据。

| 版本 | 范围 | 验收重点 |
| --- | --- | --- |
| MVP | CT 单课程、文本输入、目标/流程/评价草稿 | 路由正确、引用可见、教师可编辑、未审不发布 |
| 试点版 | CT/AE/DE 多课程、课程资产版本、教师复核记录 | 目标覆盖率、来源覆盖率、复核闭环；具体阈值待试点后确定 |
| 规模化版 | 课程群、角色权限、模板市场、导出与资产治理 | 多学院隔离、审计、版本回滚和单位经济模型可复核 |

## 3. 商业模式

- 客户与付费者：使用者为教师/课程组，预算拥有者为学院课程负责人或教师发展中心。
- 收费方式：按单门课程包、教师席位或院系空间订阅；具体价格区间和最低采购量**待补证据**。
- 获客：课程负责人示范课、教师发展中心试点、校内课程资源治理项目；不把现有代码验证当作客户订单。
- 交付：课程资产盘点 → 配置课程包 → 设计3个脱敏演示 → 教师审核 → 试点复盘 → 扩容。
- 复购：新学期内容更新、课程群扩展、教师席位增加和审计/治理服务。
- 成本：本地模型与检索资源、课程资产清洗、实施培训、运维和人工复核；单位成本需用真实调用/人工时记录测算。
- 单位经济公式：`单课程贡献毛利 = 课程包合同收入 - 资产整理人时 - 模型/检索成本 - 复核与交付人时`；当前无真实收入、成本和转化率数据。
- 三年阶段：第1年验证单课程交付；第2年扩展课程群与治理；第3年形成院系级订阅和服务标准。收入目标与市场规模**待补证据**。

## 4. 市场与竞争

目标市场边界是高校课程备课与课程资产治理，不延伸到自动授课、自动评分或未经授权的学生画像。需求证据目前来自本地场景契约、课程资产审查和教师复核要求；外部市场数字、政策和客户访谈**待补证据**。

| 替代方案 | 局限 | 差异化 |
| --- | --- | --- |
| Word/表格与人工备课 | 复用和来源追踪成本高 | 课程包、引用和复核状态结构化 |
| 通用生成式 AI | 不知道课程边界，可能编造来源 | 场景绑定课程、证据策略和“未审不发布” |
| 学校已有 LMS 资源库 | 管理资源但不一定生成目标对齐草稿 | 生成、检索、审核、发布形成一条链 |

技术壁垒是课程资产规范、证据策略、任务 Trace 和教师反馈闭环；数据壁垒是经授权的课程资产版本与复核记录；渠道壁垒是学院/教师发展中心试点；生态壁垒是 LMS、课程平台和资源发布流程。易复制部分是提示词和页面，防守方式是数据授权、审计记录、模板质量和交付流程。以上壁垒尚未等同于已验证竞争优势。

## 5. 落地计划

- 0—3个月：选1门 CT 课程，清点课程大纲与已审资产；完成6条演示；建立教师复核表；用合成输入跑路由和本地降级。
- 3—12个月：扩展到 AE/DE；记录来源覆盖、教师修改点、复核周转时间；与1个学院做授权试点。试点客户和阈值**待补证据**。
- 12—36个月：课程群模板、权限审计、版本回滚、LMS 导出和院系订阅；是否规模化取决于试点续费与成本数据。
- 团队：产品/课程专家定义目标与验收；Agent/检索工程师维护路由和证据链；前端负责演示和审核；实施负责资产清洗与培训。
- 资源：脱敏课程材料、授权教师、CPU/本地模型运行环境、可选向量库；不需要提交密钥到仓库。
- 风险与合规：版权和教师资料授权、学生隐私、错误教案、未审内容发布、模型日志脱敏；默认人工复核，发布前有审批。
- 里程碑：M1 路由/输入/输出契约通过；M2 3个教师样例完成复核；M3 试点数据形成；M4 决定是否扩展。指标阈值以试点基线为准，不虚构数字。

## 6. 路演表达

### 30秒电梯介绍

教师备课最耗时的不是“写一段文字”，而是把课程目标、已有资料、课堂活动和课后验证对齐。我们把这件事做成一个有课程边界和来源卡片的备课工作台：AI 先生成草稿，教师逐项复核，未通过的内容不发布。先从一门课程试点，再按课程群和院系空间扩展。

### 3分钟路演稿

高校课程团队面对的实际问题是资料散、复用难、来源难追踪。我们的产品绑定课程场景，而不是开放式聊天：教师输入课程目标、章节和约束，系统通过场景路由进入备课 Agent，读取授权课程资料，输出目标、先修、活动、形成性评价和来源。每个结果都带执行进度、证据卡片和人工复核状态。

商业上，使用者是教师，付费者是学院或教师发展中心，交付单位是单门课程备课工作台。先用低风险的单课程试点验证教师修改成本、来源覆盖和复核周期，再决定按课程包、席位还是院系空间收费。我们不宣称已有收入或节省比例，这些要用授权试点记录验证。技术上复用项目已有 TaskRouter、TaskRunner、课程 RAG 和非阻塞任务链；未配置正式 Provider 时，前端明确显示本地降级，不冒充云端结果。

### 5分钟答辩稿要点

价值：减少资料整理与重复排版，保留教师专业判断。可行性：能力契约、输入映射、结构化输出和 fallback 已在仓库中定义。安全：课程资产按授权使用，合成材料标记 synthetic，未审内容不自动发布。商业闭环：课程包交付 → 教师复核 → 学期更新 → 课程群扩展。现阶段最大缺口不是代码演示，而是真实教师试点、采购预算和外部市场证据，项目会把这些列为下一阶段验收而非提前宣称。

### 评委10问10答

1. **为什么不用通用大模型？** 因为本案交付重点是课程边界、来源和复核，通用模型本身不提供这些治理约束。
2. **谁真正付费？** 预算假设是学院课程负责人或教师发展中心，需通过访谈和采购文件核验。
3. **教师会不会不愿意审核？** 先把审核限定为关键节点和来源确认，并以修改时长/复核周转记录验证。
4. **生成错了怎么办？** 结果标为草稿，缺证据进入 warnings，发布动作需要人工审批。
5. **有没有真实效果？** 当前只有本地结构/路由验证，真实效果与用户结果待补证据。
6. **壁垒是什么？** 授权课程资产、版本/复核记录、场景证据策略和交付流程，而不是提示词。
7. **如何保护版权？** 只接入有授权的课程资产，记录来源和访问权限，正式策略需法务确认。
8. **能否扩展到其他专业？** 通过课程包和能力契约扩展，不修改冻结的 Solver 基线。
9. **模型没配置还能演示吗？** 可以使用明确标记的本地 Agent/降级；前端会显示运行状态。
10. **什么时候能规模化？** 只有完成教师试点、成本核算、复核指标和采购验证后，才进入规模化。
