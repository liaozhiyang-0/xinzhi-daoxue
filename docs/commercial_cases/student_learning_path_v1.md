# 案例三：学情诊断与个性化学习路径

`scenario_id`: `student_learning_path_v1`  
当前完成度：**产品、商业、演示和风险边界已闭环；真实学生试用与学习成效证据待补。**

## 1. 定位

一句话：把学生的作答证据和薄弱知识点转化为“三步学习—复测—更新”的可解释路径，不把建议当成掌握结论。

目标用户是学生和教师，付费客户是学校教务或在线教育平台；场景是课后补弱、错题复习、教师干预和课程质量分析。痛点是建议泛化、只推荐资料、不知道是否学会。市场规模、留存、学习增益和价格**待补证据**。

## 2. 产品与技术

- 形态：学生工作台+教师查看入口；输入近期作答、错误类型和目标，输出先修知识→练习→复测 checkpoint。
- 核心功能：证据摘要、分阶段路径、推荐理由、复测、状态更新和不确定性声明。
- 架构：`/workspace` → `student_learning_path_v1` → `LEARN_01_LOCAL_RETRIEVAL_V1` → 本地课程知识库/错误池 → 学习结果与复测 API；所有任务按用户/会话隔离。
- 难点：避免把一次作答当掌握、避免跨学生记忆污染、推荐与课程资料对齐、复测结果回写。
- 可行性：场景契约要求 attempt history、recommendation、retest；现有前端已读取 attempts/mastery/retests，知识 Agent 支持 `learning_advice`。
- MVP/试点/规模化：MVP 做 CT 单点路径；试点做教师复核与复测；规模化接入课程群、教务和权限。学习提升阈值待试点建立。

## 3. 商业模式

学校教务/在线教育平台付费，按活跃学生、课程包或学习路径订阅；具体价格和学生量**待补证据**。获客从一门课的课后补弱试点，交付包括课程包、错误池、教师看板和复测流程。复购来自新课程、学期续订、教师干预和学习分析。成本是知识资产、检索、模型、存储、教师服务和隐私合规。单位经济：`订阅收入 - 活跃用户计算/存储 - 课程配置 - 教师支持`；没有真实活跃/续费数据。三年路径：单课路径 → 学院课程群 → 校级学习支持服务。

## 4. 市场与竞争

边界是“证据驱动学习建议”，不做自动升学、心理或能力判定。证据来自 `config/scenarios.yaml`、学习闭环代码和 `workspace.js` 的复测展示；外部市场/政策/竞品表现**待补证据**。

| 替代 | 局限 | 本案差异 |
| --- | --- | --- |
| 学生自行刷题 | 不知道先补哪个知识点 | 建议理由来自作答证据 |
| 规则题库推荐 | 只按标签，不闭环复测 | 三步路径+checkpoint |
| 通用聊天机器人 | 容易混入别的课程或历史答案 | 课程/会话隔离、证据状态、无掌握夸大 |

壁垒是课程知识点图、错误池、复测数据与学校工作流；易复制的是对话界面，策略是授权数据、教师反馈和可审计路径。

## 5. 落地计划

0—3个月：CT 单课建立三类薄弱点、合成复测和 UI 走通；3—12个月：授权学生/教师试点，记录完成率、复测结果和教师采纳，阈值待补；12—36个月：多课程、教务看板、权限和干预闭环。团队由课程专家、学习科学/产品、Agent 工程、前端和隐私负责人组成。风险：学生隐私、画像误用、推荐偏差、未成年人数据、历史主题污染；采用最小数据、会话隔离、人工复核和明确“不代表掌握”。

## 6. 路演表达

**30秒**：我们不告诉学生“你已经学会了”，而是根据真实作答证据给出三步可执行路径，并在复测后更新建议。学校购买的是可解释的学习干预闭环，而不是一段泛化答案。

**3分钟**：学生的问题常常不是没有资料，而是不知道先补什么。系统从近期作答和错误证据出发，推荐先修概念、针对练习和复测点，每一步显示理由和限制。教师看到的是需要干预的证据，不是未经验证的排名。商业上按课程和活跃学生服务，先做单课试点，再扩展课程群。

**5分钟要点**：一次错误不等于能力；推荐不等于掌握；隐私和权限优先；只有复测证据才更新状态；没有试点前不宣称学习增益；本地检索和前端复测能力已存在，外部成效待补。

**10问10答**：1.付费者=教务/平台，待访谈；2.如何不乱推荐=要求证据与引用；3.掌握如何定义=复测与教师确认；4.跨学生污染=用户/会话隔离；5.是否排名=不做未经授权排名；6.效果数据=待试点；7.价格=按活跃学生/课程，待验证；8.教师价值=干预优先级与证据；9.隐私=最小化、权限、脱敏；10.扩展=课程包与学习闭环，不改冻结 Solver。

商业画布：学校/平台付费；价值=可解释路径和复测；渠道=单课试点；收入=课程/活跃学生订阅待验证；成本=知识配置、计算、支持和合规；伙伴=学院/LMS；关键活动=证据提取、推荐、复测、教师复核。

技术一页：作答证据 → 场景绑定 → 本地检索 Agent → 路径/复测 → learning outcome API → 状态与教师干预。竞争一页：证据、复测、课程隔离和不夸大掌握。路线一页：单课→多课程→校级。财务一页：`收入-活跃用户计算/存储-课程配置-支持`，无真实财务数。

## 7. 六个演示案例

| 编号 | 目标与输入 | 操作/路由/知识 | 输出价值 | 失败备用 |
| --- | --- | --- | --- | --- |
| D1 | CT 学生两次 KCL 作答记录 | 选场景、输入 attempts；`LEARN_01_LOCAL_RETRIEVAL_V1`；CT 本地知识 | 证据摘要和三步路径 | 无记录则明确要求补证据 |
| D2 | 只薄弱在节点法先修 | 输入错误点与目标 | 先修→练习→复测 | 知识点不在课程包则待核 |
| D3 | 复测后更新建议 | 完成 checkpoint 再刷新 | 路径状态更新 | 复测未完成不标掌握 |
| D4 | 教师查看干预证据 | 切换教师角色查看脱敏摘要 | 看到推荐理由和待干预点 | 权限失败则只展示学生本人 |
| D5 | 跨主题隔离 | 先问 CT 再问 DSP 新主题 | 无旧主题答案污染 | 发现冲突时清空/新任务 |
| D6 | 风险边界 | 要求根据一次错题判定能力 | 拒绝确定性结论，标不确定 | 前端失败时以结构化结果演示 |
