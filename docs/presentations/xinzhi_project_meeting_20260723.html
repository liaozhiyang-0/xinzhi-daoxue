大家好，今天我汇报“芯智导学”当前阶段的完整进展。我的重点不是逐个展示页面，而是回答四个问题：我们已经建成了什么、系统为什么这样设计、哪些能力已经有工程证据、下一阶段四个人具体怎么协作。

这次汇报的核心判断是：平台骨架和主要执行链已经基本形成，下一阶段不应继续横向堆功能，而要把知识库质量和真实测试集做深，让系统从“能跑”进入“可验证、可迭代”。

已有 HIGH_RISK 校验、引用校验、幂等、重试、租约、指标、评测 schema 和报告框架。

阶段判断02 / 21

这一页是整场汇报的摘要。我们已经不是一个只有想法或 Demo 的项目：统一任务链、路由、RAG、求解、前端和数据库都已经存在。

但“功能存在”不等于“教育质量可靠”。下一阶段真正决定项目上限的是两个数据资产：一是经过治理的课程知识库，二是有来源、有参考解、有评分规则的真实测试集。

产品目标：一个输入，多能力协同03 / 21

产品形态上，我们坚持学生端只有一个自然语言入口。学生不需要理解 Agent ID、Provider、Flow ID，也不应当承担技术选择。

系统内部先识别课程和任务，再判断是否需要知识库、专业工具、模型或受控云端工作流，最后把复杂过程压缩成学生能够理解的回答、证据和后续学习动作。

从架构上看，现在是一个有清晰分层的 FastAPI 单体。选择单体不是能力不足，而是当前团队规模和验证阶段下更容易保证一致性。

核心边界是：展示层不直接调用模型；所有任务通过 API 和 TaskRunner；RAG、模型和工具作为能力被编排；治理与评测横向覆盖整个执行链。

历史和学习动作

非阻塞

任务创建立即返回 202，模型调用不占用创建请求线程。

可恢复

事件 sequence、SSE 重连、历史任务、取消、受限重试与幂等。

可替换

当前 LocalTaskExecutor 可在未来替换为队列，而不改变 API 合同。

原则：不复制 TaskRunner，不复制 RAG，不复制 Provider06 / 21

这一页是理解系统最关键的一页。所有正式能力都从同一个任务入口进入，不管是知识问答、专业求解还是备课。

这样做的价值是：每个能力天然拥有同样的会话、事件、取消、重试、指标、证据和历史。未来如果需要分布式队列，只替换 TaskExecutor 边界，而不是重写业务。

能力层面已经不再局限于电路理论。专业求解覆盖四个核心课程包，教学和研究类任务由内部 Agent 承担，随机问题也有通用问答兜底。

证据校验

已经完成

索引与检索技术链、文档版本、失败保护、证据包、引用验证和调试页面已经建立。

仍然欠缺

真实资料的完整清洗、章节体系、知识点标签、图文关系、基准查询和教师级内容复核。

RAG 命中不等于答案正确；证据必须可追溯09 / 21

知识库的技术链已经比较完整：扫描、版本、切块、向量和词法检索、融合重排、引用校验都有对应模块。

但目前最大的短板不是算法，而是内容资产。课程资料是否完整、章节是否规范、知识点是否准确、图片和正文是否关联，这些都需要人工参与。下一阶段的重点就是把“技术可用”变成“知识可信”。

下一阶段我建议只抓两条主线。第一条是把知识库从“能索引”做到“内容可信、引用可追溯”；第二条是制作真实测试集，让我们能够客观知道系统在哪些题型、课程和风险点上失败。

两条线不是独立的：真实测试会暴露知识缺口，知识库改进后必须回到同一测试集验证，形成可重复的工程闭环。

重点方向 A

知识库：从“文件集合”升级为“可治理证据系统”

1. 资产盘点

课程、来源、版本、授权、格式、章节与缺失范围。

产出：manifest
2. 内容治理

标题、OCR、公式、图片、重复、知识点和人工批准。

产出：质量清单
3. 索引工程

语义切块、版本、embedding、active/history 和失败保护。

产出：可复现索引
4. 检索基准

真实查询、应命中文档、跨课程污染和图文检索。

产出：benchmark
5. 引用验收

支持结论、定位有效、版本新鲜度和无证据拒答。

产出：验收报告
优先顺序： 先做 CT、AE、DE、SS 四门核心课程的最小可信闭环，再扩展到更多课程；先保证文本证据，再逐步提升电路图和公式图像。
原始资料只读；所有修订通过配置覆盖层14 / 21

知识库工作可以拆成五个可验收的工作包。第一步不是直接调 embedding 参数，而是盘点资料和授权；第二步做内容治理；第三步才是索引。

之后必须建立检索 benchmark，最后验收引用是否真的支持结论。建议先聚焦四门核心课程，做出小而可信的闭环，再扩大规模。

真实测试集的关键不是题目数量，而是每道题有没有完整证据。每个 case 都要记录来源、参考解、判分 rubric、容差和禁止错误。

为避免自我确认，出题人和复核人要分离。存在争议的题先放入候选区，不应为了凑数量进入正式集合。真实模型测试要小批量、可追踪、控制费用。
