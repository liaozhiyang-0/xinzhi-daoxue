# 稳定性发现

## 观测到的状态

当前指标快照包含 2520 completed、95 failed、62 cancelled、85 waiting_review、2 waiting_user；最近 200 个任务中有失败和长任务。该数据包含既有历史和本轮审计产生的任务，不能计算本轮稳定率，但说明系统允许多个非终态/人工复核态并存。

SSE reconnect 在一个已终止任务上通过；队列 pending、dead-letter 和 in-flight attempts 当前为 0。刷新恢复在一个浏览器会话上通过。

## 取消稳定性

取消研究任务后，任务最终约 51 秒进入 cancelled，期间超过 40 秒保持 running。系统最终能收敛，但停止动作不是用户直觉上的即时停止。若外部调用没有可取消能力，需要在 UI 和 API 中定义明确的 `cancelling` 状态、deadline、幂等 cancel 和最终 reconciliation。

## 稳定性测试不足

没有完成 20+ 次重复任务矩阵、并发会话、服务重启后 SSE、Redis/Qdrant 短暂不可达、断网、重复提交、双击发送、超大文件和多图任务。不得把当前健康状态当作这些场景的通过证明。

## 建议的回归门槛

修复后按场景至少执行：单轮 10 次、多轮 10 次、取消 5 次、刷新恢复 5 次、SSE 重连 5 次、无匹配检索 5 次、错误上传 5 次，并记录终态收敛、答案/证据适用性和 UI 状态隔离。
