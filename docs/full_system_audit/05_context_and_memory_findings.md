# 上下文、会话与记忆发现

## 已验证

- 新建会话会清除本地 session ID、当前 task、图片材料、课程选择、intent override 和上下文面板。
- reload 后会话消息可恢复，且代码会通过 session task history 重新 hydrate 已完成任务，说明持久化恢复链存在设计。
- 页面提供“记忆设置”、会话摘要和上下文面板入口；本轮未修改记忆开关或写入长期记忆。

## P0：多轮上下文与输出约束未保持

复现：

1. 问“请简要解释电阻串联时电流和总电阻的关系。”
2. 同一会话追问“直接给出公式，不要资料说明。”

第二轮没有返回 `R_eq = R_1 + R_2` 或同等简洁公式，反而回答 KCL/KVL 方程数、解释“证据中没有欧姆定律”，并要求补充章节。它既丢失了 active topic，也没有把“不需要资料说明”作为输出约束。该行为直接破坏学习连续性和用户对追问的信任。

## 状态污染风险

同一浏览器会话中，文本问题显示此前电路图 artifact；这说明 answer panel、artifact 状态或 task presentation 的清理边界仍可能依赖旧任务。现有代码虽有 `resetConversation()` 和 `archiveCurrentAnswer()`，但运行现象证明清理没有覆盖所有可视化/结果节点，根因待定位。

## 记忆产品风险

UI 同时展示近期消息、相关历史、会话摘要和长期记忆，但回答中没有给用户清楚区分“本轮上下文”“会话摘要”“长期记忆”“课程证据”的来源边界。多轮错误已经发生时，右侧“上下文”信息不足以解释系统为什么切换到 KCL/KVL。建议在修复阶段把路由使用的上下文快照、继承/重置原因和用户可控的内容呈现出来。

## 当前结论

刷新恢复可用，但“恢复正确”不等于“回答正确”；多轮追问属于 P0，长期记忆的精度和跨会话隔离在本轮没有进行破坏性写入测试，标记为未充分验证。
