# 本地延迟优化报告

测试日期：2026-07-18；Windows 11、CPU 模式、BGE-small-zh-v1.5、SigLIP2、Qdrant local；云端调用关闭。索引版本 `RAG_f4e223885aa4c5a003d0`。

## 指标

改造前已记录热路径检索 p95 约410ms。改造后第一次60条 cache-miss/mixed 运行：60/60，检索 p50 229ms、p95 334ms，本地总 p50 233ms、p95 337ms。相对原 p95 下降76ms（约18.5%），没有因抽象翻倍。

框架微基准1000次：Route p50/p95 0.0094/0.0206ms，ExecutionPlan 0.0149/0.0320ms，InputMapper 0.0216/0.0460ms。框架本身远低于1ms。

冷启动文本模型首次请求为17,215ms，仅代表首次模型加载，不计入热路径 p95。相同请求结果缓存命中10次 p50 9ms、p95 11ms。最终代码重启后连续执行三次60条均为60/60；后两次全缓存评测检索 p95 分别11ms和12ms，总 p95分别12ms和14ms。

同一新问题的文本检索250ms，启用已预热图片检索323ms，图片增量73ms。首次图片模型加载案例为8,777ms；普通文本计划跳过图片即可避免这项冷加载。完整测试后 Reranker 仍为 `loaded=false`，因此普通问答避免了其全部加载和推理开销；本轮未主动加载大型 Reranker，不能诚实给出其毫秒节省值。

并发 cache-miss：并发2批次776.5ms，请求本地756/757ms；并发4批次976.0ms，请求本地411–958ms。均未超过1秒，但并发4已接近目标边界。图片模型加载后工作集约1,280–1,285MB；仅启动、模型未加载时健康检查确认三模型均为 lazy。本轮 PowerShell CPU采样未获得可信增量，故不报告虚构CPU峰值。

## 优化点与瓶颈

BM25/Dense受控并行；Embedding/Image/Reranker有并发闸门；模型首次加载有锁；图片和Reranker按计划跳过；缓存含策略、索引和模型修订；HTTPX连接池复用。当前主要瓶颈仍是CPU Embedding、首次图片加载和并发4时的模型排队。建议部署前显式预热文本模型，图片按业务需要预热，继续保持普通问答禁用Reranker。

开发环境可通过 `POST /api/v1/debug/rag/prewarm` 显式加载指定模型；生产环境禁用该端点。带600ms本地预算的普通纯文本请求若发现图片模型尚未加载，会标记 `rag_status=degraded` 并跳过可选图片冷启动；真实图片输入不执行此跳过。
