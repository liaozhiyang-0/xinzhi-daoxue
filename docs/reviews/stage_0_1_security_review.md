# 阶段 0—1.5 安全审查

## 审查结论

通过，未发现已跟踪真实密钥或原始星辰 YAML。

## 已确认

- `.env`、`.local_inputs/`、`.local_outputs/`、本地数据库和存储目录被 Git 忽略。
- Docker build context 排除原始输入、本地输出、历史归档和中文本地资料目录。
- 敏感文件扫描区分环境变量名称与真实值，CI 不需要星辰 Secret。
- 日志遮罩 API Key、Token、Secret、密码和带密码连接串。
- API 响应不返回堆栈；500 使用统一安全错误。
- 文件上传校验扩展名、MIME、空文件、大小和路径穿越，并计算 SHA-256。
- 数据库提交失败时清理已保存对象。
- 调试页面不保存 API Key，也不调用星辰。
- 解析器使用公开节点编号，不输出原始内部 ID、提示词、代码或敏感字段值。

## 审查中发现并已修复

1. 高：原文件名只使用 `Path.name`，反斜杠路径在 Linux 上可能绕过。已同时拒绝 `/` 和 `\`。
2. 高：上传后数据库失败可能留下脏对象。已增加回滚清理。
3. 高：旧星辰 Provider 存在未来误触发 HTTP 的可能。已删除网络代码。
4. 中：日志只有键级遮罩。已增加字符串与连接串遮罩。
5. 中：缺少自动检查原始 YAML 是否被跟踪。已增加 `check_sensitive_files.py`。

## 保留风险

- 本阶段不解析不可信 PDF，也不提供公开下载；后续若增加解析或下载必须增加隔离、内容嗅探和授权。
- 开发 Compose 默认密码只适合本机，进入共享环境前必须替换。
- 原始 YAML 尚未提供，因此真实导出内容的脱敏结果当前为 BLOCKED，不能声称已扫描该文件。
