## 1. 科研场景真实模型验收

**范围：** G2-01、G2-06、G2-14、G2-15 及同类科研场景。

**待解决问题：**

- 使用真实 Provider 和真实 Agent 完成端到端任务，不以 Mock、本地固定答案或单元测试替代真实验收。
- 核对 Agent 路由、模型调用、检索证据、结构化输出、失败/降级状态和前端展示是否一致。
- 对每个场景保留可审计的任务 ID、Provider/模型、模型调用次数、SSE 事件序号、证据状态和发布门结果。

**完成标准：** 每个场景至少完成一轮真实模型验收；结果明确区分“模型生成成功”“证据充分”“可发布通过”，不得将前两者混同为最终通过。

## 2. 准生产运行稳定性验证

**范围：** 并发任务、SSE 重连、取消/重试、双 Worker 竞争。

**待解决问题：**

- 验证多任务并发创建和执行时，任务状态、Redis lease、队列消费和资源隔离不互相干扰。
- 验证 SSE 断线重连后事件顺序、去重、补发和最终终态一致。
- 验证任务取消、超时、Provider 失败和重试的幂等性、终态转换及审计记录。
- 验证 API 内置 Worker 与独立 Worker 同时运行时不会争抢 lease、重复执行或导致 Worker 异常退出。

**完成标准：** 在接近生产的运行配置下完成并发、断线、取消、重试和双 Worker 场景验证；所有任务都有唯一终态，事件序列可恢复，且无重复执行、悬挂任务或错误成功。

## 3. 课程资料、教师复核与最终发布门禁

**范围：** 当前因课程证据不足或需要教师确认而处于 `completed_with_gaps` / `publishable=false` 的结果。

**待解决问题：**

- 补齐对应课程的教材、讲义、实验条件、评价标准和可引用资料，并建立可追溯的资料版本与来源。
- 由教师复核模型生成的事实、公式、课程边界、活动安排、安全约束和评价标准。
- 明确证据充分性、数学/结构化输出质量、人工复核和风险提示的发布前置条件。
- 确保资料不足、教师未确认或质量检查未通过时，只能进入待复核状态，不得自动发布。

**完成标准：** 资料证据充分、教师复核完成、质量门禁全部通过后才允许 `publishable=true`；否则保持明确的待复核终态，并在前后端展示未通过原因。
