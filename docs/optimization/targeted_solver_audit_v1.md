# 统一学术求解器定向审计 v1

## 1. 审计范围与证据

本审计只覆盖 `ACADEMIC_PROBLEM_SOLVER`、模型路由、CT 旧基线回退、
AE/DE 课程能力、学生答案审查、边界控制和相关契约。没有修改冻结的
`SOLVER_CT v1.0`，也没有重建评测系统。

基线证据来自
`真实测试题/统一格式/evaluation_reports/full_live_20260727T120134Z`：

- 336 个案例，执行成功率 88.39%，39 个硬超时；
- 严格答案准确率 80/145，已评分条件准确率 80/106；
- 100 个案例出现模型路由回退，占 29.76%；
- 错误检测 1/12，边界遵循 6/12；
- P50 约 67 秒，P90/P95 接近 180 秒。

这些文件是本机私有测试证据，不作为公共代码或公开数据提交。

## 2. 当前调用链

```text
POST /api/v1/tasks
  -> TaskRouter（课程、任务族、Agent）
  -> TaskRunner
     -> 单次 RAG 检索与上下文组装
     -> ACADEMIC_PROBLEM_SOLVER
        -> 题目结构化（复用 canonical_input）
        -> 边界策略
        -> 可选图片理解
        -> 统一 AcademicProblemSolverGraph
           -> 课程包分型
           -> 能力选择
           -> 确定性工具
           -> 风险分级与本地质量门
        -> 主模型生成
        -> AE/DE 确定性专业验证
        -> 条件式高风险验证
        -> REVIEW/VERIFY 审查
        -> 受控回退决策
        -> 统一结果与教学适配
     -> 仅在明确批准时调用 SOLVER_CT_V1
     -> SSE/任务结果持久化
```
Graph 中的“规划、求解、校验、修正”节点多数是本地编排阶段，并不各自
独立调用大模型。真正的模型调用集中在图片理解、图片汇总、主生成、续写和
可选的二模型高风险验证中。

## 3. 节点依赖和调用次数

| 任务类型 | 主要调用 | 优化前风险 | 本轮控制 |
|---|---:|---|---|
| 简单文本题 | 1 次主生成 | 可能因统一校验或误判截断继续调用 | 规则判定为 simple，默认不做大模型二次校验 |
| 中等文本题 | 1 次主生成，显式截断时可续写 | 续写与校验叠加 | 生成预算 2，软截止后停止可选调用 |
| 复杂题 | 主生成与必要续写，最多 3 次 | 完整重写、二次验证导致串行增长 | 条件验证、局部冲突标记、最终整理预留 |
| 高风险题 | 生成、必要验证或一次专业回退 | 多层回退或回到原 Agent | `fallback_count` 默认最多 1，记录完整路径并阻止循环 |
| 1–4 张可拼接图片 | 1 次图片理解 + 1 次主生成 | 无完成标记时重复整份答案 | 短题不再仅因缺少私有完成标记续写 |
| 多图逐图模式 | N 次并发图片理解 + 1 次汇总 + 1 次主生成 | 图片串行、重复汇总 | 有界并发、汇总只执行一次、结果写回同一结构化题目 |
| REVIEW/VERIFY | 1 次内部参考生成或本地已有结果 + 确定性审查 | 把诊断当作重新解题 | 独立模式，只返回第一处实质错误或指定目标验证 |

显式 `finish_reason=length` 是调用预算的受控例外：允许在续写上限内完成被
Provider 明确截断的答案；普通短题不会因为未输出内部完成标记而重复生成。

## 4. 超时来源

1. 图片理解、主生成和续写依次串行，长题会累计多个 Provider 延迟。
2. 历史案例中存在“答案已经完整，但未输出内部完成标记”，系统又发起续写，
   第二次回答常重复第一份完整答案。
3. 模型路由的 primary 与 fallback 都不可用时，单个逻辑调用实际产生两次
   Provider 尝试；历史 `model_calls[].fallback_used` 因此计入 100 个回退。
4. 高风险验证在生成之后启动，如果前序阶段已接近 180 秒，会把已有答案拖到
   最外层硬超时。
5. 旧实现只有单次调用超时和最外层任务超时，缺少请求级“停止新增工作并整理
   已有答案”的预算。

## 5. CT、AE 高回退的实际原因

全量报告中的 100 个“回退”按课程包括 CT 38、AE 40、DE 21、SS 1。
抽查调用轨迹显示，这一指标按任意 `model_calls[].fallback_used` 计数，主要是
Spark/Qwen 模型路由在 primary 失败后尝试 fallback；它不等价于 100 次
`SOLVER_CT_V1` 专业基线执行。多例中 primary 和 fallback 均在约 5 秒后返回
`model_provider_unavailable`。

此外，原 Graph 对 CT 高风险路径较宽，只要产生 `fallback_target`，TaskRunner
就可能进入旧 CT 基线；格式问题、低置信度和真正的专业失败没有被区分。
本轮把模型路由回退与旧 CT 专业回退统一纳入单请求回退账本，并要求
`fallback_decision.approved=true` 才能执行旧基线。

AE 的高回退还与题型分型较窄有关。原课程包虽然能识别 BJT、MOS、运放，
但缺少静态/小信号、反馈、频响、功放、波形、比较器和稳压电源的完整标签，
也缺少器件工作区和增益符号的确定性验证。遇到不确定工作区时，系统更容易把
“可条件化回答”当成整体失败。

## 6. AE、DE 专业能力缺口

AE 原路径主要依赖课程 Prompt 和通用质量门，缺少以下本地检查：

- 静态工作点与交流小信号模式混用；
- BJT/MOS 偏置条件与所用工作区公式是否自洽；
- 理想运放虚短的线性负反馈前提；
- 共射/共源增益负号；
- `v_o/v_i` 与 `v_o/v_s` 的定义差异。

DE 原路径也主要依赖通用 Prompt，缺少：

- 小变量逻辑表达式的真值表穷举；
- 候选式与参考式的反例；
- 状态机逐有效时钟沿模拟；
- 算术右移符号扩展；
- 连续更新与边沿更新的冲突检查。

## 7. 错误检测失败原因

旧链路先完成整题求解，再从聚合学生文本中进行通用核对。学生步骤与
`step_id` 没有稳定绑定，错误类型依赖全文关键词，最后常把第一步当成错误位置。
这使“第一处实质错误”指标即使发现了某个错误，也可能因步骤定位错误而失败。

本轮将 REVIEW/VERIFY 变成独立模式：按步骤顺序先运行课程和通用确定性规则，
遇到第一处错误立即返回结构化反馈，不默认重写整份参考答案。

## 8. 边界控制失败原因

原有“不编造”主要存在于 Prompt，无法稳定拦截缺图、缺公式、缺 ROC、未知
逻辑态、概率分布非法、条件矛盾等确定性情形；生成模型仍可能给出猜测值或
绝对化断言。边界答案状态也没有统一区分 `conditional`、`unusable`。

本轮在模型调用前增加代码层边界策略。可确定的边界案例直接返回缺失项、
可继续性、假设和条件化结论，避免为明显不可解输入支付模型调用。

## 10. 风险与回滚

- 规则验证器是有限覆盖，不代表完整 AE/DE 形式化证明；
- Provider 真实延迟和可用性仍需完整 336 例验证；
- 多图逐图识别仍可能产生多个并发调用，受图片数量和预算影响；
- DSP、COMM 的有效评分样本不足，本轮未做课程 Prompt 过拟合；
- REVIEW 未命中确定性规则时会返回低于完整形式化证明的置信度。

回滚应使用可审查的提交反向提交，不使用会覆盖用户工作区的 reset：

```bash
git log --oneline
git revert <commit>
```
