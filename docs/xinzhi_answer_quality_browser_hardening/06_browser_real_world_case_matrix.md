# 06 浏览器真实用户问题矩阵

## 一、要求

优先使用：

```text
用户现有真实题库
人工复测已经发现问题的题
真实电路图
真实多图题
```

不要主要依赖 mock。

---

# 二、普通文字解题

至少：

```text
15
```

覆盖：

CT / AE / DE / SS。

---

# 三、困难题

至少：

```text
15
```

要求真正多步。

---

# 四、怪题

至少：

```text
10
```

包括：

- 条件不足
- 冲突
- 错误前提
- 单位陷阱
- 口语
- 错别字
- 非标准公式

---

# 五、单图

至少：

```text
10
```

真实图片。

---

# 六、多图

至少：

```text
15
```

真实素材优先：

```text
题干+图
题目+答案
总图+局部
连续页
图A+图B
```

---

# 七、多轮

至少：

```text
8 Session
```

每个：

```text
8~15 turns
```

---

# 八、自由问答

至少：

```text
15
```

例如：

```text
为什么 RC 电路会这样？
帮我看这组实验数据。
这两种方法有什么区别？
我这一步是不是错了？
不要完整答案，只提示。
```

---

# 九、审批专项

专门投喂：

```text
20 个本不该审批的问题
```

确认不进入 waiting_review。

---

# 十、浏览器验收总量

建议：

```text
100~150 个真实浏览器 Task
```

不要机械追求数字。

重点是：

> 所有关键产品行为必须在浏览器里看过。

---

# 十一、输出

```text
docs/audit/42_browser_real_world_matrix.md
```
