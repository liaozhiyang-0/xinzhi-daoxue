# 02 回答质量合同

## 一、核心原则

一个任务不是只要 `completed` 就算成功。

最终回答必须满足：

```text
Relevant
Complete
Actionable
Consistent
Honest
```

---

# 二、专业解题默认回答合同

对于学生专业题，默认应包含：

## 1. 直接识别问题

说明要解什么。

## 2. 给出关键方法

但不要无意义长篇模板。

## 3. 完成主要计算/推导

## 4. 给出最终答案

这是硬要求。

除非题目确实无法唯一求解。

## 5. 若条件不足

优先：

```text
明确假设
→ 给一般解/参数化解
```

而不是只让用户补充。

---

# 三、禁止“伪完成”

以下都判失败：

```text
只给思路不给答案
只说需要复核
只提示边界
只说图片不清楚
只说建议人工审核
```

如果系统其实可以继续。

---

# 四、降级回答最低合同

即使发生：

```text
RAG empty
图片局部模糊
工具不可用
外部 Provider 失败
```

仍应尽可能输出：

```text
已确认信息
明确假设
当前可完成推理
可给出的结果
剩余不确定性
```

---

# 五、答案长度

用户没有特别要求时：

优先：

```text
清晰
完整
不冗余
```

避免固定模板导致：

```text
先复述题目
再讲学习目标
再讲知识点
最后才回答
```

---

# 六、追问模式

如果用户问：

```text
为什么这里是负号？
```

回答局部问题。

不要重新完整解题。

---

# 七、用户已有过程

用户给了自己的步骤时：

优先从其过程继续。

不要全部推翻重做，除非第一步就错。

---

# 八、Semantic Grade

浏览器真实答案分：

```text
A = 完整、正确、直接可用
B = 核心正确，有轻微缺失
C = 有帮助但明显不完整
D = 错误/拒答/无答案
```

普通题目标：

```text
A+B >= 95%
```
