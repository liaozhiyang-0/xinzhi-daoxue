# 六案例数学公式渲染审计

## 1. 审计目标

六案例会覆盖电路、信号与系统、科研和教学内容中的数学表达。当前前端统一使用：

```text
Markdown → remark-math → rehype-katex → KaTeX CSS/字体
```

渲染器位于 `apps/web/src/components/MarkdownRenderer.tsx`，避免不同页面各自维护一套公式转换逻辑。

## 2. 输入兼容规则

渲染前只做边界明确的分隔符归一化：

- `$...$` 和 `\\(...\\)` 作为行内公式；
- `$$...$$` 和 `\\[...\\]` 作为块级公式；
- 保留 `\\begin{...}`、矩阵、联立方程和对齐环境；
- 普通 Markdown、代码块和表格内容不应被当作公式重写。

长公式使用滚动容器，避免页面横向布局被撑破。出现 KaTeX 解析异常时，Error Boundary 显示原始内容和可复核提示。

## 3. 覆盖夹具

当前 `apps/web/src/math/fixtures.ts` 包含 31 条夹具，至少覆盖：

| 类型 | 代表表达式 |
| --- | --- |
| 阻抗 | `Z_C` |
| 卷积 | 积分形式的卷积 |
| 电流 | `i_C` |
| 微分 | 偏导表达式 |
| DFT | 求和形式 |
| 矩阵 | `bmatrix` |
| 分段 | `cases` |
| 对齐 | `aligned` |
| 相量 | `10∠30°V` |

检查脚本：

```powershell
cd apps/web
npm run math:check
```

脚本验证夹具数量和关键表达式存在性；实际浏览器渲染还应在构建后检查字体加载、长公式滚动和失败回退。

## 4. 六案例对应关系

- TP-01：教学目标、反馈放大器公式和课堂例题；
- FE-01：电路推导、符号一致性和错误步骤复核；
- LP-01：卷积、傅里叶和采样概念的解释性表达；
- RB-01：科研结果中的定量表达和不确定性；
- KG-01：版本和治理内容通常以结构化文本为主，但必须能安全展示公式字段；
- AC-01：电路拓扑、节点方程、相量、饱和边界和人工复核说明。

## 5. 验收标准

通过标准：

1. 31 条夹具检查通过；
2. TypeScript 类型检查通过；
3. production build 通过；
4. 公式失败时不丢失原始文本；
5. 长公式不造成页面不可横向滚动；
6. 结果区仍按“结论 → 证据 → 限制 → 下一步”组织。

当前构建已通过。Vite 报告的 chunk size warning 来自 KaTeX 资源体积，不影响构建正确性；后续如需要优化首屏性能，可把公式渲染资源改为按需加载，但不应牺牲失败回退和公式覆盖范围。
