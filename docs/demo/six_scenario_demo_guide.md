# 六大 Agent 演示案例使用指南

## 1. 目标与统一展示链

本阶段固定六个演示案例，用来展示同一套任务运行链在不同业务边界下的差异：

```text
用户任务 → 任务理解 → 制定计划 → 调用能力 → 证据/状态 → 验证/复核 → 最终结果
```

前端展示的是可审计执行轨迹，不展示模型私有推理链。每个案例都应该明确：输入是什么、调用了哪些能力、证据是否充分、是否需要人工复核，以及下一步行动是什么。

## 2. 六个案例

| 编号 | 案例编号 | 演示名称 | 业务定位 | 主要能力 |
| --- | --- | --- | --- | --- |
| 1 | TP-01 | 教师智能备课 | 将课程目标和学生差异组织成可执行教案 | Planner、RAG、Teaching Skill |
| 2 | FE-01 | 作业首错诊断 | 定位最早实质错误并解释错误传播 | Verification、Failure Attribution、Learning Loop |
| 3 | LP-01 | 学生个性化学习路径 | 根据学习状态规划下一阶段学习 | Learning State、Experience、Planner |
| 4 | RB-01 | 科研前沿证据简报 | 在范围约束下整理研究证据和不确定性 | Search/RAG、Evidence Governance |
| 5 | KG-01 | 学院知识库治理 | 审查版本、来源、权限和发布边界 | Version、Permission、Governance |
| 6 | AC-01 | 模拟电路题图诊断 | 结合电路图、求解工具和验证边界分析问题 | Vision、Solver、Tool、Verification |

## 3. 各案例演示输入与验收重点

### TP-01：教师智能备课

建议输入：为反馈放大器设计一节 90 分钟课堂，给出教学目标、课堂流程、例题、分层练习和形成性评价，并标出需要教师确认的课程版本或基础假设。

重点看：

- 是否先澄清教学对象、课程版本和先修知识；
- 是否给出可执行的时间分配，而不是泛泛的课程介绍；
- 是否把课程资料证据和教师待确认项分开；
- 是否给出课堂后的验证任务。

### FE-01：作业首错诊断

建议输入：提交一道电路题的完整分步解答，要求定位最早出现的实质错误，说明它如何影响后续步骤，并给出一个不直接替学生做完的验证任务。

重点看：

- 是否定位“首错”，而不是只指出最后答案不对；
- 是否区分概念错误、建模错误、符号错误和计算错误；
- 是否解释错误传播链；
- 是否留下学生可以独立完成的复核任务。

### LP-01：学生个性化学习路径

建议输入：提供卷积、傅里叶级数、傅里叶变换、采样、拉普拉斯等主题的历史成绩，要求制定下一阶段学习路径并说明优先级、前置知识和验证任务。

重点看：

- 是否把学习状态转成有顺序的计划；
- 是否识别前置关系，而不是简单按分数排序；
- 是否为每个阶段定义可观察的完成条件；
- 是否说明新测评结果如何更新后续路径。

### RB-01：科研前沿证据简报

建议输入：限定时间范围和研究主题，要求整理研究问题、方法、证据来源、局限和待核实结论；没有可靠来源支持的定量结论不得补写。

重点看：

- 是否遵守时间、主题和文献类型边界；
- 是否把来源、结论和推断分层；
- 是否明确冲突证据和未核实内容；
- 是否避免把检索结果写成无依据的确定性结论。

### KG-01：学院知识库治理

建议输入：审查一份 2026 版课程资料更新，判断其与 2025 版的替代关系、来源风险、教师备注权限、发布前检查和学生可见性。

重点看：

- 是否给出版本关系和可回滚关系；
- 是否识别来源不明、教师备注和权限风险；
- 是否把“允许发布”和“需要审批”区分开；
- 是否保留审计依据，而不是只输出一个发布结论。

### AC-01：模拟电路题图诊断

建议输入：上传运算放大器电路图，要求先判断线性负反馈状态，再说明虚短、虚断能否使用，推导关键节点关系，并指出输出饱和边界、读图不确定处和人工复核假设。

重点看：

- 是否真正读取附件并展示附件名称；
- 是否先判断拓扑和适用条件，再进行公式推导；
- 是否区分图像证据、模型假设和计算结果；
- 当拓扑或参数不清时，是否输出“需要补充信息”，而不是编造确定结论。

当前示例图片路径为 `/debug-assets/question-bank/analog-opamp.jpg`。前端保留 `AC-01` 业务案例标识，并沿用现有图像解题路由；不新增 Agent 或修改场景启用状态。

## 4. 启动与演示

前端开发检查：

```powershell
cd apps/web
npm run typecheck
npm run math:check
npm run demo:check
npm run smoke
npm run build
```

浏览器打开：

```text
http://localhost:8000/workspace?demo=1
```

进入后从左侧六张案例卡选择案例。案例 6 会自动加载示例图片到待上传材料区域；文件选择器不会被脚本强行写入，浏览器原生 `input[type=file]` 的文件列表为空是正常安全限制，实际提交使用 React 中保留的 `File` 对象。
